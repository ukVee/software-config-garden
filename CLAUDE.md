# software-config_garden

Implementation repo for **soft-fig** — the program that combines machine memory (the CLAUDE.md garden schema), templating, symlink deployment, integrated VCS, and the Keeper client into one tool. Installed by building from source; prebuilt release channels (AUR, `.deb`, …) are planned.

## Status

**M1a + M1b + M1c + M1d + M2a + M2b + M2c done (2026-05-05 → 2026-05-16); M-onboard done (2026-05-26); M3a done (2026-05-30); M3b done (2026-05-31); M3b vault-surface follow-up done (2026-06-01); M4a (deploy spine) done (2026-06-02).** This garden is self-hosting under signed VCS history with two encryption layers at three granularities: Layer A whole-garden ciphertext, Layer B per-file selective secrets, and M2c per-region inline `<vault id="…">…</vault>` secrets. The daemon mounts a FUSE plaintext-view at the garden root when configured with a relocated `state_root`; sealed paths (matching `.softfig/vault/sealed-paths.toml` globs) are encrypted under per-file HKDF subkeys and projected as `[sealed:<path>]\n` placeholders. Files containing inline `<vault>` tags get per-region HKDF subkeys, base64-inline ciphertext on disk, and `<vault id="…">[encrypted]</vault>` projected through FUSE on read. `softfig reveal <path>` writes plaintext to a 0600 file under `$XDG_RUNTIME_DIR` and commits a `vault_reveal` audit intent; the `--id <id>` repeatable flag reveals just one or more region plaintexts. The same `softfig-keeperd` binary handles M1c-compat, M2a, M2b, and M2c configs from one binary; Layer B is inert until the first `sealed-paths.toml` lands and inline-region encryption is inert until `<vault>` bytes appear in a tracked file.

**M-onboard** adds the first-run front door: `softfig onboard` scaffolds a fresh garden from an embedded default-layout skeleton (`templates/default-garden/`, baked in via `include_dir!`), inits the Vault, and writes a born-in-FUSE genesis commit directly in the `state_root` layout — no plaintext is ever written at the garden root, and the three-phase `migrate` dance is reserved for converting the legacy tablet garden. The scaffold logic lives in the frontend-agnostic `softfig-onboard` crate so a future MCP tool wraps the same `onboard()` entry point. The daemon now resolves its config via `KeeperConfig::discover` (reads `<garden>/.softfig/keeper.toml`), so a born-in-FUSE or migrated garden boots straight into FUSE mode. Install plumbing is a documented runbook (`docs/onboard-laptop.md`) plus `scripts/onboard-device.sh`.

**M3b** adds the first Keeper *human* surface: `softfig-tui`, a ratatui frontend over the daemon (master/detail Browse + History + Action forms + in-app unlock). It introduces two **read-only** IPC verbs — `list_tree` and `read_file` — that serve garden content from the committed tip and apply the same `LayerBHook` redaction the FUSE read path uses, so the TUI receives `[sealed:<path>]` / `[encrypted]` projections, never sealed plaintext. The TUI is a separate binary; the lean-core slice keeps vault reveal/seal surfaces CLI-only for now.

**M4a** opens the **templating + symlinks pillar** (the `bombadil link` replacement) with its static deploy spine: a new frontend-neutral `softfig-deploy` crate (`plan` diff / `apply` I/O) + a thin `softfig deploy [--dry-run] [--force]` CLI. It materializes a declarative `config/deploy.toml` source→target table onto the real filesystem. Because the garden's plaintext is FUSE-only and ephemeral (it vanishes on lock), a direct symlink to a source would dangle — so `apply` materializes each source to a **persistent plaintext deploy-cache** (`~/.local/share/softfig/deployed/`, dir `0700` / files `0600`) and symlinks the target → the cache file (bombadil's `.dots/` model, survives lock); a dot may opt into `method = "copy"` to write the bytes straight to the target with a `# managed by softfig` stamp. Reads + writes are native FS — no new IPC verb; deploy requires the garden unlocked. M4a is **`$HOME` targets + regular-file dots only**; templating (MiniJinja, M4b), Vault secret resolution + posthooks (M4c), and `/etc` deploy are deferred. Sources move into a garden `config/{source,docs}` tree at the future dogfood ceremony.

**M5a (transport + pairing) — COMPLETE (2026-06-09 → 2026-06-10)** opens the **cross-device sync pillar** with its foundation slice: two daemons discover each other, mutually authenticate, establish an end-to-end-encrypted channel (LAN-direct or relayed), and persist each other in a signed network trust ring. **No data crosses yet** (that's M5b+). New frontend-neutral **`softfig-net`** crate (12th member): an application-level **Noise** tunnel (`snow`; `XX` for first pairing, `IK` for reconnect; X25519 + ChaCha20-Poly1305) over plain TCP carrying a **protobuf** (`prost`) control plane; **SAS** short-code pairing (six decimal digits from the `XX` handshake hash, confirmed out of band — defeats a LAN MITM, no camera); an Ed25519 **attestation** binding each device's identity key to its X25519 transport static; the signed **`peers.toml`** network trust ring (distinct from the unlock-ACL `trust.toml`); **mDNS** LAN discovery (`_softfig._tcp`); and a **zero-trust relay** (a blind ciphertext dumb-pipe through the always-on server for off-LAN peers, ring-authorized — no open relay). The transport key is a separate X25519 key minted at vault init beside the Ed25519 identity (auto-generated on unlock for existing vaults). **M5a-4** makes it operable: `softfig-keeperd` hosts the `softfig-net` instance on unlock (inbound listener + mDNS responder + optional relay listener), four new IPC verbs `pair_begin`/`pair_confirm`/`pair_list`/`pair_remove`, and the `softfig pair`/`peers`/`unpair` CLI. WireGuard was **rejected** — keeperd is an unprivileged user unit and WG's `CAP_NET_ADMIN` would re-break the FUSE/no-privilege model. **No new VCS intents** (M5a writes only vault-internal keys + `peers.toml`). The live two-device handshake + mDNS + relay forward is the documented manual real-machine smoke step (no multicast / second host / TTY in the sandbox). M5c (multi-ref union-mount), M5d (shared-subtree keying), M5e (write-turn sync) follow — see the garden's `meta/spec-sync.md` + `journal/decisions/decision-softfig-m5a-impl.md`.

**M5b (zero-knowledge device-chain replication) — DONE (2026-06-14)** is the **first slice where data crosses devices**. The chain owner pushes its signed, content-addressed device-chain **ciphertext** to explicitly-authorized backup hosts that **verify and store it but cannot decrypt it** (off-device backup + point-in-time DR via the VCS history). Reading peer documents stays out — deferred to a later **M5b-view** slice (a chain-scoped read subkey, not master key M). New **data-plane protobuf** in `softfig-net` (`control.proto` field nums 100+: `ReplicaGrant` / `GetTip` / `TipAnnounce` / `GetCommit` / `CommitData` / `GetTree` / `TreeData` / `GetObject` / `ObjectData` / `ReplicaDone`) + a frontend-neutral `replica` module: the `ReplicaSource` / `ReplicaSink` traits, the `serve_replication` (owner) + `pull_replication` (host, sink-driven) drive loops, **fast-forward-only** fork/rollback detection (a single honest owner never forks → a non-fast-forward is rejected + alarmed, never force-updated), and the domain-separated tip-announce / grant signing-byte helpers + verifiers. keeperd hosts it: `RepoSource` over a read-only `Repo` handle + a vault-signed announce, a keyless per-peer `MirrorStore` (reuses `softfig-store` `Db` + `ObjectStore` at `<replica_root>/<owner-id>/.softfig/`, verifies per-commit signature + hash + owner-binding, tree canonical addresses, object content addresses), a `GrantLedger` (`replica.toml` `push_to`), and the inbound-serve dispatch + owner push driver + a periodic reconcile loop (which doubles as the tip-driven pull-on-connect catch-up). **Two-sided consent:** `keeper.toml [replica] host` (static host opt-in, same posture as `[relay]`) + an owner-minted **signed grant** from `push_to` — pairing alone authorizes nothing. New IPC verbs `replica_grant` / `replica_revoke` / `replica_status` + `softfig replica grant|revoke|status`. **No new VCS intents** (the mirror is a verified copy, not an authored chain). Live two-device replication over real mDNS/relay is the manual real-machine smoke step; the loopback-TCP serve/pull/verify/fast-forward path is covered headlessly (`tests/m5b_replica.rs`). See the garden's `journal/decisions/decision-softfig-m5b-impl.md` "Update 2026-06-14 — landed".

**growlight (autonomous work-loop pillar) — Phase 2a DONE (2026-06-14)** is a new garden pillar + softfig feature driving an iterative *fresh-session work loop*: each session is reseeded from a curated **baton** (a pointer index, not a context dump), works one chunk against a **backlog** of milestones (→ ordered slices) and standalone tasks, hands off by rewriting the baton, and a fresh session continues — the bet being that a curated baton beats a lossy `/compact` (never compact; always `/clear`-reseed). Built device/agent-generalized for AUR distribution (no hardcoded paths; Claude Code is a documented agent backend behind a seam). **Phase 1** shipped the four daemon-mediated MCP verbs that maintain the pillar (`log_baton` / `add_backlog_item` / `add_slice` / `set_item_status`), reusing the small-files machinery: a shared `actions/numbering.rs` (`.seq`), the managed-region **authoritative queue table** in `growlight/backlog/CLAUDE.md` that owns each item's status + order (≤1 `active`, idempotent re-set), and lowercase-slug ids; `growlight/baton-log/` is excluded from the backlink graph (audit-only). **Phase 2a** adds **`softfig growlight init`** — an idempotent, daemon-mediated retrofit (mirrors `migrate split`) that materializes the `growlight/` pillar via that same verb machinery: the routing `CLAUDE.md`, the embedded `protocol.md` / `session-policy.md` templates (`templates/growlight/`, `include_str!`), and the backlog + baton-log skeleton, all folded into one `growlight_initialized` commit (no commit when nothing changed; self-healing for a partial pillar), plus best-effort + idempotent **§14 nav wiring** of the root `CLAUDE.md` (top-level-map bullet + boundary-table row, via a surgical "insert after the last list/table line" helper) and `meta/{reserved-filenames, conventions}.md`. The two budgets the loop honors (context 50/60 % ROLL; 5h-session 85 % HALT) read from `usage.json` (statusline-emitted at this phase; growlightd writes it too as of task 048). **Phase 2b** adds **`softfig growlight start`** — the launcher + the churny runtime under `$XDG_CONFIG_HOME/softfig/growlight/` (derived, never literal): it resolves the garden root from a read-only daemon STATUS query, requires the pillar present, then writes (plain fs ops, no IPC/commit) the generated `loop.json` (a SessionStart hook that re-injects `inject.sh` on both `startup` and `clear` — the `/clear` roll mechanism — plus a `statusLine` → `statusline.sh`), the two 0755 helper scripts (`inject.sh` cats the garden `protocol.md` + the runtime `baton.md` to stdout; `statusline.sh` tees `{context_window, rate_limits, ts}` to `usage.json` and prints a compact budget line), and seeds `baton.md` + `questions.md` once (never clobbering an in-flight loop). It then launches `claude --name softfig-loop --settings <loop.json>` (the documented agent-backend seam) or stops at `--no-launch`; warns when `jq` (the budget read path) is absent. The real-garden dogfood (install bins + cycle the daemon, then run `init`/`start`) is next. See the garden's `meta/spec-growlight.md` + `journal/decisions/decision-growlight-loop.md`.

**config-in-garden — Slice 1 + Slice 2 DONE (2026-06-15)** moves the daemon's per-garden config *inside* the garden so it is encrypted-at-rest, VCS-versioned, M5b-backed, and editable through the FUSE mount — instead of plaintext beside the vault under `<state_root>/.softfig/`. The framing that unlocked the simple design: each device's garden is its **own source of truth** (M5b is a one-way ciphertext mirror, never a merge), so one in-garden config doesn't bleed settings across devices. **Slice 1** lifts the post-unlock policy into `config/keeper.toml` (`GardenConfig` = `[net]`/`[relay]`/`[replica]`/`[reveal]`); the daemon overlay-reads it at unlock (after FUSE mount, before net start) via `KeeperConfig::apply_garden_config`, **falling back to the pointer when absent** (non-breaking). The plaintext `.softfig/keeper.toml` pointer shrinks to bootstrap-only — `state_root` (read *before* unlock to find the vault) + `[growlight] allow_relock` (kept OFF the agent-writable garden surface so the loop can't self-enable relock). **Slice 2** splits the trust ring at its root: slow-changing **membership** (device id / name / transport key / attestation / `paired_at`) → in-garden `config/peers.toml` (committed on pair/unpair only); volatile **endpoints** (host:port mDNS refreshes constantly) → a local `.softfig/peers-endpoints.toml` sidecar, **never committed** — so a discovery sighting can't fire a commit on every mDNS tick. `softfig-net` gains `EndpointCache` (load/save/`capture`/`apply`) + `Ring::to_membership_toml` (endpoints stripped); keeperd's `load_ring(garden_root, state_dir)` reads membership from the garden (legacy `.softfig/peers.toml` fallback) + merges the sidecar, the pairing handlers write membership through one self-write-suppressed write + a `peers_changed` commit, and the mDNS browse loop writes only the sidecar. `softfig migrate config [--apply]` (daemon-mediated, dry-run default, idempotent) lifts `config/keeper.toml` **and** the legacy ring's membership into `config/peers.toml` in one `config_migrated` commit (legacy ring absent ⇒ peers no-op; endpoints re-seeded into the sidecar). New VCS intents `config_migrated` (Slice 1) + `peers_changed` (Slice 2); onboard scaffolds `config/keeper.toml` but **not** an empty `config/peers.toml` (first pairing creates it). See `journal/decisions/decision-softfig-config-in-garden.md`.

**queue-v2-scheduling (queue redesign milestone 2/3) — DONE (2026-10-17; merged to `main` `25a4237`)** completes the scheduling half of the queue redesign (spec-growlight-queue, stacked on `queue-v2-state`), entirely behind the §11 `queue = "legacy" | "v2"` switch — default `legacy` keeps today's behavior byte-identical, and an unknown value is refused at arm time (disabled fleet, never silently legacy). growlightd gains the fail-closed v2 queue source (mount-read `queue.toml`/`queue-archive.toml`/`slices.toml`, alert-once), the pure `pick_v2` (the §2 eligibility + four-step pick, the §4 unit walk with a closed list of skip reasons), the §6.3 handshake (member verb → validate → commit → entry baton → terminate after `roll_grace_secs` → pick, with §9 preemption and the backend-mismatch pause), the §7 cap (follow-ups ≤ 5, sub-milestones ≤ 2 deep, close-out → `growlight_block`), and the §6.7 member write limits (the `> Model:` guard, the slice-body subset rule, member gating of the human verbs). The `> Model:` resolver moves into `softfig-ipc::model_choice` (comma lists, the sub-milestone chain, backend match, the member default) so the CLI and growlightd share one resolver. **`SOFTFIG_MEMBER`** is the member-identity seam: growlightd writes it into both backends' MCP `env`, softfig-mcp reads it once at startup and stamps it on every request, and keeperd holds the request to the write limits — identity comes from the launch env, never a tool argument, and a garbled value refuses fail-closed. `softfig growlight queue pick [--member <id>]` prints the assignment and every skip reason. See `meta/spec-growlight-queue.md` (§2, §4–§7, §9, §11) and `journal/decisions/decision-growlight-queue-redesign.md`.

FUSE on unlock.

## Crypto + canonicalization

- AEAD: XChaCha20-Poly1305 (Vault blob layer)
- Hash: BLAKE3 (object addresses, tree hashes, commit hashes)
- Password KDF: Argon2id (OWASP 2023 default `m=64 MiB, t=3, p=4`)
- Subkey KDF: HKDF-SHA-256
- Signing: Ed25519 (identity key, signs each commit's hash)
- Recovery phrase: BIP39 12-word
- **Canonicalization for hashing/signing: RFC 8785 JCS** via `serde_jcs`. Trees, commits, and intent payloads all canonicalize through it.

Blobs use **master-keyed convergent encryption** so the VCS layer can content-address ciphertext and dedup: `nonce = BLAKE3-keyed(M, plaintext)[..24]`, `per_blob_key = HKDF-SHA-256(salt=nonce, ikm=M, info="softfig.blob.v1")`, `blob_file = varint(master_key_id) ‖ nonce ‖ AEAD-body`. Same plaintext + same M → same ciphertext → same hash. Indistinguishable without M.

Commits are signed by hashing the canonical commit form first: `commit_hash = BLAKE3(JCS({parent, root_tree, author_device, author_pubkey, intent, payload, master_key_id, timestamp}))`, then `signature = identity.sign(commit_hash)`. Verifiers re-canonicalize, re-hash, and check both the hash matches the stored row and the Ed25519 signature verifies under `author_pubkey`.

on every accept. Daemon boots in **Locked** state; only `status`
and `unlock` are answerable until `unlock` succeeds. All M3a/M3b +
small-files write verbs require Unlocked.
`migrate_finalize` requires `state_root` to be set in `keeper.toml`
AND the daemon to have an active FUSE mount. **M5a-4**: `pair_begin` /
`pair_confirm` / `pair_list` / `pair_remove` (cross-device pairing; require
Unlocked). `pair_begin` runs the blocking Noise `XX` handshake with the daemon
mutex released and parks the result; `pair_confirm` persists the peer into
`peers.toml`. The daemon hosts the `softfig-net` instance (inbound listener +
mDNS + optional `[relay]`) on unlock. **Pairing-UX Slice A**: `discover_list`
(read-only; require Unlocked) surfaces the mDNS discovery cache's
nearby-but-unpaired devices `{name, fingerprint, endpoint, last_seen_secs}` as
the LAN pick-list — filtered against the ring + this device, fed by the TXT
`nm` name field. **M5b**: `replica_grant` / `replica_revoke` / `replica_status`
(require Unlocked) — owner-side controls for zero-knowledge device-chain backup.
`replica_grant`/`revoke` edit the `replica.toml` `push_to` allow-list (grant
requires the fingerprint to name a paired ring member); `replica_status` returns
backup-health metadata only (`{host, push_to, hosted[]}`), never peer documents.
**Task `058`** turned that from membership into health: `push_to` is now
`Vec<PushTarget>` (`{fingerprint, name, last_ok, last_ok_age_secs, stale, state,
state_since, detail}`) and `HostedChain` gained `last_sync_age_secs` + `stale`.
The staleness verdict is the **daemon's** (`replica_health::STALE_AFTER_SECS`,
24h) so the CLI and the TUI cannot disagree about what "stale" means, and
`state` keeps the diagnoses apart: `no-route` / `unpaired` mean we never dialed
(fix discovery, the endpoint cache, or the pairing), `error` means a route
existed and the push failed (fix transport or auth).
The replication data plane rides the existing Noise sessions (not the IPC socket):
the host serves the inbound listener's `ReplicaGrant`-first sessions into a
keyless per-peer mirror, and the owner's reconcile loop dials granted hosts.
