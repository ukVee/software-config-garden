# Trademark policy

> Plain-language policy, not legal advice. It states where the project draws the
> line between its code licence and its name; it is not a registration and makes
> no claim that any mark is registered.

## The short version

**`AGPL-3.0-or-later` covers the code. This policy covers the name and the logo.
Neither replaces the other.** The licence gives you broad rights to use, study,
modify and redistribute the source. It does not give you the right to call your
version of it soft-fig.

## Reserved names and marks

The names **"soft-fig"** and **"softfig"**, the project logo, and the visual
identity of the project's documentation are reserved for the maintainer. This is
about avoiding confusion — a user must be able to tell the maintainer's project
from a fork — not about restricting the code.

These marks are not registered. This policy is the project's stated position and
the basis on which permission is granted or refused.

## Use that is fine

You do not need permission to:

- **Refer to the project by name** in prose, reviews, tutorials, comparison
  tables, conference talks, or a bug report.
- **Say your work relates to it**, truthfully: "a fork of soft-fig",
  "compatible with soft-fig", "a pack for soft-fig", "built on soft-fig".
- **Redistribute an unmodified copy** under its own name, keeping this policy and
  `LICENSE` intact — for example packaging it for a distribution.
- **Use the name in a URL, repository name, or handle** for a fork, as long as the
  fork is clearly labelled as a fork and not presented as the project itself.

## Use that needs permission

Ask first (unkownvee@protonmail.com) before:

- Using the name or logo as (or in) the name of a **modified redistributed
  version**, a product, a hosted service, or a company.
- Using the logo in a way that suggests endorsement, sponsorship or official
  status.
- Registering a domain, package name, app-store listing or social handle that
  could reasonably be mistaken for the project's own.

## Forks that redistribute a modified version

**Rename it.** A fork that distributes a modified version must use a different
name and must not imply that it is soft-fig or that the maintainer endorses it.
"Soft-fig Pro", "softfig-cloud" and similar names are not permitted for a
modified distribution, because a user cannot tell which project they are running.

Keeping the name is fine for a **private** fork you never distribute, and for an
**unmodified** redistribution (see above).

## No warranty of mark clearance

Nothing here is a statement that the name is free of third-party claims in your
jurisdiction, and nothing here is legal advice. If you are unsure whether a use is
permitted, ask — the answer is usually yes.
